# lab_data/

Каталог для лабораторных данных по диагностике сервопривода
**Delta ASDA-B3-E** (учебный стенд `stand-01`).

Каталог исключён из git (см. корневой `.gitignore`), кроме `.gitkeep` и
этого `README.md`. Все собранные данные хранятся **локально**.

> Все безопасностные ограничения из `Plan.txt` (раздел «Безопасный
> протокол экспериментов») имеют приоритет над любыми командами ниже.
> CLI **не управляет приводом**: Servo ON/OFF, движение, стоп — это
> делает оператор через основной UI или физические органы управления.

---

## 1. Структура

```
lab_data/
  stand_passport.csv              # паспорт стенда (один раз на стенд)
  experiments.csv                 # журнал всех экспериментов
  raw/<SID>.sqlite3               # сырая телеметрия (TelemetryLogger)
  exports/telemetry_<SID>.csv     # стандартизированный CSV для статьи
  runners/                        # (опц.) автогенерированные .bat-обёртки
  README.md
```

`SID` (session_id) — единый идентификатор записи, формат:

```
<EXPERIMENT_ID>_R<NN>_<YYYYMMDD>_<HHMMSS>
например:  A1_HOLDING_SERVO_ON_R01_20260612_103000
```

Получить SID можно командой:

```
lab sid A1_HOLDING_SERVO_ON 01
```

## 2. Что вводится вручную, что автоматически

| Поле                                   | Источник                                       |
|----------------------------------------|------------------------------------------------|
| `drive_model`, `drive_serial`          | вручную по шильдику                             |
| `motor_model`, `motor_serial`          | вручную по шильдику                             |
| `rated_current_A`                      | SDO `0x6075` (мА → А), если подключено          |
| `rated_torque_Nm`                      | SDO `0x6076` (мН·м → Н·м), если подключено      |
| `max_motor_speed_rpm`                  | SDO `0x6080`, если подключено                   |
| `experiment_id`, `session_id`, метки   | вручную (CLI или UI)                            |
| `ts`, `statusword`, `position`, …      | автоматически из `samples` (SQLite)             |

Все колонки и допустимые значения меток описаны в `core/csv_schema.py`.
Валидатор `tools.validate_lab_csv` забракует любые отклонения от схемы.

## 3. Единая точка входа: `lab.bat`

Все команды собраны в `lab.bat` в корне проекта. Запускать из корня:

```
lab help                 общая справка
lab test                 pytest по лабораторному слою
lab passport             паспорт стенда без подключения
lab passport-connect     паспорт стенда с автозаполнением из EtherCAT
lab record    ...        запись телеметрии + строка в журнал
lab dry-record ...       то же, без подключения (отладка CLI)
lab export    ...        SQLite -> стандартизированный CSV
lab validate  <CSV>      проверка одного CSV
lab validate-all         проверка всех CSV в lab_data\exports
lab run       ...        record + export + validate одной командой
lab A1 <REP>             готовый пресет под опыт A1
lab A2 <REP>  ...        ... аналогично для всех опытов плана
```

Сигнатура `lab run` и `lab record`:

```
lab run <EXP> <REP> <regime> <risk> <load> <dir> <vel> <dur_s> <anom> "<comment>"
```

* `EXP`     — идентификатор опыта, латиница и `_`, напр. `A1_HOLDING_SERVO_ON`.
* `REP`     — двузначный номер повторности, напр. `01`.
* `regime`  — белый список: `idle holding acceleration constant_speed deceleration reversal cyclic load_low load_medium synthetic_anomaly`.
* `risk`    — белый список: `normal transition elevated_load pre_emergency_proxy fault`.
* `load`    — `no_load`, `inertia_small`, `inertia_medium`, …
* `dir`     — `cw`, `ccw`, `both`, `none`.
* `vel`     — целевая скорость, RPM (для журнала; CLI **не** даёт команду).
* `dur_s`   — длительность записи в секундах.
* `anom`    — `0` для реальных данных, `1` для синтетических аномалий.

## 4. Подготовка стенда (один раз)

1. Подтвердить модель привода и двигателя по шильдикам.
2. Проверить крепление, кабели, свободный вал, отсутствие людей в зоне.
3. Убедиться, что доступен аварийный стоп.
4. Создать паспорт стенда:

```
lab passport-connect
```

Если привод не подключён или EtherCAT недоступен:

```
lab passport
```

В обоих случаях файл попадёт в `lab_data\stand_passport.csv`.

## 5. Готовые инструкции для всех опытов плана

> Перед каждой записью: запустить UI (`python main.py`), вывести привод
> в нужный режим (Servo ON, удержание, требуемая скорость и т. п.),
> убедиться в отсутствии ошибок. Затем — выполнить команду из таблицы.

### Блок A. Базовые штатные режимы

Цель: baseline нормы. Повторов **по 3** на каждый опыт.

| ID  | Что готовит оператор в UI                       | Команда                              |
|-----|--------------------------------------------------|--------------------------------------|
| A1  | Servo ON, вал неподвижен                         | `lab A1 01` / `lab A1 02` / `lab A1 03` |
| A2  | Servo ON, удержание после короткого перемещения  | `lab A2 01` / `lab A2 02` / `lab A2 03` |
| A3  | Servo ON, постоянное вращение по часовой 300 RPM | `lab A3 01` / `lab A3 02` / `lab A3 03` |
| A4  | Servo ON, чередование CW/CCW, ±300 RPM           | `lab A4 01` / `lab A4 02` / `lab A4 03` |

Пресеты A1–A4 уже включают: `record + export + validate`, длительность,
правильные `regime_label`/`risk_label`/`load_type`/`direction` из плана.

### Блок B. Разгон, торможение, реверс

Цель: переходные процессы. По 3 повторности.

| ID  | Что делает оператор в UI                          | Команда                                |
|-----|----------------------------------------------------|----------------------------------------|
| B1  | Профиль 0 → 600 RPM → 0, низкое ускорение         | `lab B1 01..03`                        |
| B2  | Профиль 0 → 900 RPM → 0, среднее ускорение         | `lab B2 01..03`                        |
| B3  | Профиль 0 → 1200 RPM → 0, **разрешённое резкое**  | `lab B3 01..03`                        |
| B4  | Реверс: +600 RPM ↔ −600 RPM                        | `lab B4 01..03`                        |
| B5  | Циклический туда–обратно, 5 минут                  | `lab B5 01..03`                        |

### Блок C. Разные скорости

Цель: влияние скорости на ток/момент/стабильность. По 3 повторности.
Двигаться **по ступеням**, не начинать с C5.

| ID  | Скорость в UI | Команда                  |
|-----|----------------|--------------------------|
| C1  |   300 RPM     | `lab C1 01..03`          |
| C2  |   600 RPM     | `lab C2 01..03`          |
| C3  |   900 RPM     | `lab C3 01..03`          |
| C4  |  1200 RPM     | `lab C4 01..03`          |
| C5  |  1500 RPM     | `lab C5 01..03`          |

### Блок D. Длительная циклическая работа

Цель: тепловая динамика, длинные временные ряды (по 1–2 повторности).

| ID  | Режим                                          | Команда           |
|-----|------------------------------------------------|-------------------|
| D1  | Цикл туда–обратно, низкая скорость, 10 мин     | `lab D1 01`       |
| D2  | Цикл туда–обратно, средняя скорость, 10 мин    | `lab D2 01`       |
| D3  | Цикл с частыми разгонами/торможениями, 10 мин  | `lab D3 01`       |

### Блок E. Контролируемая нагрузка (только после согласования)

| ID  | Нагрузка                          | Команда           |
|-----|-----------------------------------|-------------------|
| E1  | Небольшой инерционный диск        | `lab E1 01`       |
| E2  | Средняя добавленная инерция        | `lab E2 01`       |

`E2` помечен как `pre_emergency_proxy` — это **proxy**, не реальная авария.
**Останавливать** опыт при росте тока, шуме, вибрации, росте температуры,
ошибке статусворда или нестабильности связи (см. план, §17 «Останавливать
опыт при…»).

### Блок F. Искусственные аномалии (без стенда)

Эти записи делаются программно поверх ранее снятых нормальных CSV
(см. план, §8 «Получение предаварийных данных без реальной аварии»).
Сейчас в репозитории отдельного `tools.inject_synthetic_anomaly` нет —
готовый scaffolding под него можно добавить отдельной задачей.
Все такие сессии **обязаны** иметь `is_artificial_anomaly = 1` и
явное упоминание в `operator_comment`.

## 6. Типовой цикл для одного опыта

Пример для A3, повторность 01:

```
# 1. оператор готовит стенд в UI:
#    - Servo ON
#    - режим CSV (velocity), задаём 300 RPM, CW
#    - вал свободен, защиты в норме
# 2. запускаем готовую команду:
lab A3 01
```

`lab A3 01` под капотом выполнит:

1. `python -m tools.start_lab_session ...` — запишет `samples` в
   `lab_data\raw\A3_ROTATE_ONE_DIR_R01_<TS>.sqlite3` и добавит строку в
   `lab_data\experiments.csv`.
2. `python -m tools.export_lab_csv ...` — пересоберёт CSV в
   `lab_data\exports\telemetry_A3_ROTATE_ONE_DIR_R01_<TS>.csv` с
   прокинутыми `experiment_id / session_id / labels`.
3. `python -m tools.validate_lab_csv ...` — проверит схему, метки,
   монотонность `t`, обязательные поля.

После записи оператор обязан в UI **снять Servo ON** (или вывести
привод в безопасное состояние) перед следующим опытом.

## 8. Тесты

```
lab test
```

Запустит `tests\test_lab_layer.py` — это **полностью оффлайн** набор
тестов (синтетический SQLite, фейковый pysoem-slave), проверяющий:

* порядок и состав колонок схем;
* экспорт `samples → CSV`;
* `t = ts − first_ts` и монотонность;
* отказ экспорта на пустой БД;
* декодирование флагов statusword;
* приёмку валидного CSV;
* отклонение CSV без обязательных колонок и с неверными метками;
* отклонение немонотонного `t`;
* warning при `error_code ≠ 0` для `normal`;
* отказ метаданных с пустыми ID и неизвестными метками;
* один заголовок в `experiments.csv` после многократных дозаписей;
* запись и автозаполнение `stand_passport.csv` (включая случай с
  фейковым контроллером `pysoem`).

Если этот набор зелёный, лабораторный слой готов к публикации.
